# リポジトリのメンテナンス

既存の合意と現在の実態を比較し、必要な修正・追加・統合・削除を行う。変更不要なら、その根拠を示して終了する。

最初に[共通の作業規則](../../references/workflow.md)を読む。対象の作業先、過去の合意と適用記録、未コミット変更を確認する。記録がなくても既存構成を調べられるが、生成元や管理範囲を推測で確定しない。

## 進め方

1. 見直しのきっかけと対象を確認する。指定があれば、その問題を中心に調べる。コード、依存、検証環境、開発手順、エージェント環境の変化を必要な範囲で確認する。
2. 以前の合意・適用内容と現在の状態を比べる。人が変更した箇所、他ツールの管理箇所、不要な仕組み、情報不足を区別する。過去の適用状態へ自動的に戻さない。
3. 拡張の見直しには[拡張の選定](../../references/extensions.md)、関連リポジトリの見直しには[参照設定](../../references/related-repositories.md)を読む。追加だけでなく、維持・統合・無効化・削除を検討する。
4. 差分、理由、影響、復旧方法、検証を示す。手動変更との競合、主要方針の変更、依存追加、削除範囲が未合意なら、その判断を相談する。
5. 合意した対象だけを適用・検証する。途中で失敗したら、適用済み・未適用と復旧方法を示す。無関係なユーザー変更を巻き戻さない。
6. 現在の合意と適用記録を更新し、成功・失敗・未実行・対象外を報告する。検証後に対象が変わった場合は、影響する検証をやり直すか未確認に戻す。

プラグイン本体の更新だけを理由に、導入先の方針や成果物を変更しない。本プラグインの無効化・削除を依頼された場合は、[導入・削除手順](../../README.md)を参照し、共有キャッシュと導入先成果物の扱いを区別する。
